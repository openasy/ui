# Design decisions

What every OpenAsy product is built to do, and why. The source of truth is `docs/decisions/` in this repository; change a decision with a pull request.

| # | Decision | Area | Status |
| --- | --- | --- | --- |
| 0001 | Every product runs alone, with the others and with third-party tools | Architecture | Accepted |
| 0002 | Authentication: local accounts, MFA and single sign-on | Security | Accepted |
| 0003 | Authorization: per-product roles and scoped tokens | Security | Accepted |
| 0004 | Customization: white-label and feature switches | Product | Accepted (white-label) · Planned (feature switches) |
| 0005 | Accessibility: WCAG 2.2 AA, tested in CI | Quality | Accepted |
| 0006 | Languages: English first, ready for translation | Product | Planned |
| 0007 | Theme: light, dark and follow the system | Product | Accepted |
| 0008 | Open source: AGPL-3.0 products, Apache-2.0 library, developed in public | Project | Accepted |
| 0009 | Use the latest libraries | Engineering | Accepted |
| 0010 | Forward-only upgrades, no backward compatibility | Engineering | Accepted |
| 0011 | SQLite by default | Architecture | Accepted |
| 0012 | Daily backups and point-in-time restore | Operations | Planned |
| 0013 | Secure by default | Security | Accepted |
| 0014 | API-first | Architecture | Accepted |
| 0015 | Your data stays yours | Privacy | Accepted |
| 0016 | One container per product, signed | Operations | Accepted |
| 0017 | Every product can be monitored | Operations | Accepted |
| 0018 | One application per product; agents on hosts are separate | Architecture | Accepted |
| 0019 | Versioning: independent SemVer per product, monthly releases | Engineering | Accepted |
| 0020 | Long-term support: one LTS line per year | Engineering | Accepted |
